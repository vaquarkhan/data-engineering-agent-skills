# Incident Recovery Checklist

Use this checklist during production data incidents.

## Containment

- [ ] Bad publishes are blocked if necessary
- [ ] Affected datasets and time windows are identified
- [ ] Key consumers are informed

## Recovery

- [ ] The safest recovery option is chosen
- [ ] Rerun, replay, rollback, or backfill behavior is understood
- [ ] Recovery is validated before reopening publish paths

## Follow-up

- [ ] The incident is documented
- [ ] A new guardrail, check, or runbook update is added
- [ ] The root cause is not left as tribal knowledge
